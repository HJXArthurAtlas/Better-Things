# Feature Specification: 定义任务数据模型（TaskItem）

**Feature Branch**: `002-taskitem-data-model`

**Created**: 2026-09-21

**Status**: Draft

**Input**: User description: "YouTrack 卡 BT-8：定义 TaskItem 数据模型。字段：标题（必填）、备注（可选）、创建时间、完成状态、完成时间；置于共享核心包。验收：模型可构建，支持按创建时间排序读取。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 任务实体具备完整字段与默认值 (Priority: P1)

开发者创建一个新任务实体时，实体具备待办任务所需的全部字段：标题、备注、创建时间、
完成状态、完成时间；各字段的可空性与默认值符合需求文档（BT-A-2 §1）的约定——
新建任务默认未完成、完成时间为空、创建时间自动取当前时刻。

**Why this priority**: 字段契约是 BT-9 存取层与全部界面特性的地基，字段缺失或类型
错误会在下游放大为返工。

**Independent Test**: 在核心包测试中构造任务实体，断言各字段类型、默认值与可空性。

**Acceptance Scenarios**:

1. **Given** 指定标题创建任务，**When** 检查实体字段，**Then** 标题与传入一致，备注为空，完成状态为未完成，完成时间为空，创建时间自动生成。
2. **Given** 指定标题与备注创建任务，**When** 检查实体字段，**Then** 备注与传入一致。

### User Story 2 - 完成状态变更保持时间不变量 (Priority: P2)

任务的完成/取消完成操作自动维护完成时间：标记完成时记录完成时刻，取消完成时清除
完成时刻。任何时刻"未完成却有完成时间"或"已完成却无完成时间"都是非法状态。

**Why this priority**: 完成时间是"已完成"分组展示（BT-11）与后续排序的依据，不变量
破坏会直接产生用户可见的错误。

**Independent Test**: 在核心包测试中对任务执行完成/取消完成操作，断言完成状态与完成
时间的联动。

**Acceptance Scenarios**:

1. **Given** 一个未完成任务，**When** 标记为完成，**Then** 完成状态为已完成且完成时间为标记时刻。
2. **Given** 一个已完成任务，**When** 取消完成，**Then** 完成状态为未完成且完成时间为空。

### User Story 3 - 模型可被持久化机制注册 (Priority: P3)

开发者将任务实体注册到项目的持久化机制时注册成功——这是 BT-9 存取层得以实现的
前提，也是"模型可构建"验收的可执行化表达。

**Why this priority**: 注册失败意味着模型定义与持久化机制不兼容，但它是 P1/P2 的
自然推论，优先级最低。

**Independent Test**: 在核心包测试中把任务实体类型注册到持久化机制，注册成功。

**Acceptance Scenarios**:

1. **Given** 任务实体类型，**When** 将其注册到持久化机制，**Then** 注册成功无错误。

### Edge Cases

- 标题为空字符串时：实体允许构造（空标题的拦截属于录入层职责，BT-10），但字段契约
  必须明确标题为必填语义。
- 完成时间被外部赋值而完成状态未变时：本特性不引入额外校验拦截，状态联动只能通过
  完成操作方法发生（由测试固定该行为）。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 任务实体 MUST 包含标题字段，语义必填，类型为文本。
- **FR-002**: 任务实体 MUST 包含备注字段，可为空，类型为文本。
- **FR-003**: 任务实体 MUST 包含创建时间字段，创建时自动取当前时刻。
- **FR-004**: 任务实体 MUST 包含完成状态字段，新建任务默认为未完成。
- **FR-005**: 任务实体 MUST 包含完成时间字段，可为空，未完成时为空。
- **FR-006**: 系统 MUST 提供"标记完成"操作：置完成状态并记录完成时刻；以及"取消完成"操作：清除完成状态并清空完成时刻。
- **FR-007**: 任务实体 MUST 支持按创建时间排序读取（字段可比较）。
- **FR-008**: 任务实体 MUST 定义于共享核心包，应用外壳不得自定义同类实体。
- **FR-009**: 任务实体 MUST 能被项目的持久化机制注册。

### Key Entities *(include if feature involves data)*

- **TaskItem（任务）**: 待办事项的持久化实体。属性：标题（文本，必填）、备注（文本，可空）、
  创建时间（时刻，自动）、完成状态（布尔，默认未完成）、完成时间（时刻，可空）。
  行为：标记完成、取消完成（维护完成状态与完成时间的联动）。关系：无（单实体）。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 核心包测试套件覆盖 US1/US2/US3 全部验收场景并全部通过。
- **SC-002**: 应用外壳源码中对持久化机制的直接引用数仍为 0（边界未因新实体被破坏）。
- **SC-003**: 模型注册到持久化机制的冒烟验证通过。

## Assumptions

- 持久化机制采用项目技术栈的默认方案（plan 阶段确定），本特性不引入存取接口（BT-9 范围）。
- 标题非空的录入拦截在录入层（BT-10）实现，模型层不做断言拦截。
- 排序读取的查询接口属于 BT-9；本特性只保证排序键（创建时间）存在且可比较。
