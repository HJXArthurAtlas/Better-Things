# Feature Specification: 主窗口任务管理（添加/完成分组/编辑/删除撤销/布局/键盘）

**Feature Branch**: `004-main-window-task-management`

**Created**: 2026-09-21

**Status**: Draft

**Input**: User description: "YouTrack 卡 BT-14（主窗口布局+空状态）、BT-10（添加）、BT-11（完成与已完成分组）、BT-12（编辑）、BT-13（删除与撤销）、BT-17（键盘操作）——六卡共享主窗口交互面，一体实现。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 添加任务（BT-10，P1）

用户在主窗口顶部的输入框输入标题，按回车即创建任务；新任务出现在未完成列表最顶部；
输入为空白（含纯空格）时不创建；回车后输入框清空并可连续输入。

**Why this priority**: 添加是待办工具的第一动作。

**Independent Test**: 运行应用 → 输入标题回车 → 列表顶部出现该任务；输入空白回车 → 无变化。

**Acceptance Scenarios**:

1. **Given** 应用运行中，**When** 输入「买牛奶」回车，**Then** 列表顶部出现「买牛奶」且输入框清空。
2. **Given** 输入框内容为空或纯空格，**When** 按回车，**Then** 不创建任务，列表无变化。
3. **Given** 创建了任务后，**When** 退出应用并重新打开，**Then** 任务仍然存在（持久化）。

### User Story 2 - 完成与已完成分组（BT-11，P1）

勾选任务复选框即标记完成；完成的任务从未完成列表消失、出现在「已完成」分组；
取消勾选即恢复到未完成列表。

**Why this priority**: 勾选完成是待办工具的第二基础动作。

**Independent Test**: 勾选一个任务 → 它移入已完成分组且记录完成时间；取消勾选 → 回到未完成列表。

**Acceptance Scenarios**:

1. **Given** 未完成列表有一个任务，**When** 勾选它，**Then** 它从未完成列表消失、出现在「已完成」分组。
2. **Given** 「已完成」分组有一个任务，**When** 取消勾选，**Then** 它回到未完成列表顶部按序排列。

### User Story 3 - 已完成分组可折叠（BT-14，P2）

「已完成」分组显示完成数量，点击分组标题可折叠/展开；应用刚启动时默认折叠。

**Independent Test**: 完成一个任务 → 分组标题显示数量 → 点击折叠 → 内容隐藏 → 再点展开。

**Acceptance Scenarios**:

1. **Given** 已完成分组有 2 个任务，**When** 点击分组标题，**Then** 分组在折叠/展开间切换且标题显示「已完成 (2)」。

### User Story 4 - 编辑任务（BT-12，P2）

双击任务打开编辑面板，可修改标题与备注；确认后列表与持久化同步更新；取消编辑
则保持原样。

**Independent Test**: 双击任务 → 修改标题与备注 → 确认 → 列表显示新内容；重启后仍在。

**Acceptance Scenarios**:

1. **Given** 一个任务，**When** 双击打开编辑、修改标题与备注并确认，**Then** 列表立即显示新标题与备注。
2. **Given** 编辑面板打开，**When** 点击取消，**Then** 任务保持修改前的内容。

### User Story 5 - 删除与撤销（BT-13，P2）

右键菜单「删除」或选中后按 ⌫ 删除任务；⌘Z 可撤销最近一次删除，任务以原字段
（含完成状态与完成时间）恢复。

**Independent Test**: 删除一个已完成任务 → ⌘Z → 任务原样恢复（仍处于已完成分组）。

**Acceptance Scenarios**:

1. **Given** 一个已完成任务，**When** 删除后按 ⌘Z，**Then** 任务恢复且仍在已完成分组、完成时间不变。

### User Story 6 - 空状态与键盘操作（BT-14/BT-17，P3）

无任务时列表区显示引导文案；⌘N 聚焦新建输入框；↑↓ 在列表中移动选中项；
⌫ 删除选中任务。纯键盘可完成新建→选择→删除全流程。

**Independent Test**: 清空全部任务后看到引导文案；⌘N 输入框获得焦点；方向键移动高亮；⌫ 删除。

**Acceptance Scenarios**:

1. **Given** 应用无任何任务，**When** 查看列表区，**Then** 显示引导文案而非空白。
2. **Given** 任意时刻，**When** 按 ⌘N，**Then** 新建输入框获得焦点且可立即输入。
3. **Given** 列表有选中任务，**When** 按 ↓ 或 ↑，**Then** 选中项相应移动；**When** 按 ⌫，**Then** 选中任务被删除。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 主窗口 MUST 包含顶部新建输入框、未完成任务列表、「已完成」折叠分组三个区域。
- **FR-002**: 添加操作 MUST 在回车触发；空白输入 MUST 被忽略（先去除首尾空白再判断）。
- **FR-003**: 新任务 MUST 出现在未完成列表顶部（最新创建时间倒序）。
- **FR-004**: 勾选/取消勾选 MUST 经任务实体的完成操作发生，不得绕过完成时间不变量。
- **FR-005**: 「已完成」分组 MUST 显示完成数量并支持点击折叠/展开，启动时默认折叠。
- **FR-006**: 双击任务 MUST 打开编辑面板，支持修改标题与备注，确认生效、取消不变。
- **FR-007**: 删除 MUST 提供右键菜单与 ⌫ 两个入口，且 MUST 支持 ⌘Z 撤销最近一次删除并完整恢复字段。
- **FR-008**: 无任务时 MUST 显示引导文案。
- **FR-009**: ⌘N MUST 聚焦新建输入框；↑↓ MUST 移动列表选中项；⌫ MUST 删除选中任务。
- **FR-010**: 本特性全部数据操作 MUST 经共享核心包的存取器，应用源码零持久化引用。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 全部单元测试与既有测试通过（`swift test`）。
- **SC-002**: 运行时验收：添加→完成→编辑→删除→撤销→重启后数据持久，全链路截图取证。
- **SC-003**: 边界检查 CLEAN；应用构建成功。

## Assumptions

- 编辑面板以模态面板呈现（双击打开），不引入独立窗口。
- 撤销栈深度沿用系统默认（足够的单人使用强度）。
- 列表选中项的可持有标识需为应用侧通用类型——计划阶段为任务实体补充通用唯一标识字段。
