# Feature Specification: 实现 TaskStore 任务存取与持久化

**Feature Branch**: `003-taskstore-crud`

**Created**: 2026-09-21

**Status**: Draft

**Input**: User description: "YouTrack 卡 BT-9：实现 TaskStore 增删改查与持久化。新增、删除、更新（完成状态、标题、备注）、按创建时间倒序读取、启动自动加载、数据自动保存；附单元测试。验收：CRUD 单元测试全部通过；写入后重建容器数据仍在。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 任务集合的增删改查 (Priority: P1)

开发者通过任务存取器添加任务、删除任务、修改任务（标题、备注、完成状态），
并读取任务集合——集合始终按创建时间倒序排列（最新任务在最前，与需求文档
"新任务置顶"一致）。

**Why this priority**: 增删改查是全部界面特性（BT-10~13）的唯一数据入口。

**Independent Test**: 在内存存取器上执行添加、修改、删除操作，断言集合内容与顺序。

**Acceptance Scenarios**:

1. **Given** 空存取器，**When** 依次添加三个任务，**Then** 集合含三个任务且按创建时间倒序。
2. **Given** 存在若干任务，**When** 删除其中一个，**Then** 集合不再包含它，其余保持原序。
3. **Given** 存在一个任务，**When** 修改其标题、备注并标记完成，**Then** 集合中的实体反映全部修改。

### User Story 2 - 数据落盘后可完整重建 (Priority: P2)

写入的任务数据（含完成状态与完成时间）被保存；以同一存储位置重新打开存取器时，
全部任务及字段完整读回——"写入后重建容器数据仍在"。

**Why this priority**: 本地优先（宪法 III）的核心承诺；加载正确性决定应用重启体验。

**Independent Test**: 向指定存储位置的存取器写入任务并保存，用同一位置新建第二个
存取器，断言数据一致。

**Acceptance Scenarios**:

1. **Given** 存取器写入两个任务（其一已完成）并保存，**When** 用同一存储位置新建存取器，**Then** 读到两个任务，标题、完成状态、完成时间全部一致。
2. **Given** 第一个存取器删除一个任务并保存，**When** 再次用同一位置重建存取器，**Then** 被删任务不再出现。

### User Story 3 - 打开即加载，无需手动刷新 (Priority: P3)

存取器初始化完成后，既有数据立即可用——使用者不需要调用额外的"加载"动作；
内存模式（测试/预览用）不触碰任何磁盘位置。

**Why this priority**: 它是 Story 2 的使用面表达，依赖落盘先成立。

**Independent Test**: 用含既有数据的存储位置初始化存取器，不调用任何加载方法，
直接断言集合内容。

**Acceptance Scenarios**:

1. **Given** 存储位置含两个任务，**When** 初始化存取器后立即读取集合，**Then** 两个任务按创建时间倒序就绪。
2. **Given** 以内存模式初始化存取器，**When** 读取集合，**Then** 为空且不产生任何磁盘文件。

## Edge Cases

- 对同一任务先完成再取消完成再保存：重建后应为未完成且完成时间为空（不变量跨持久化成立）。
- 存储位置首次使用（无历史数据）：初始化应成功且集合为空，不报错。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 存取器 MUST 提供添加任务操作（标题、可选备注），返回新建实体。
- **FR-002**: 存取器 MUST 提供删除任务操作。
- **FR-003**: 存取器 MUST 以只读集合暴露任务，按创建时间倒序排列。
- **FR-004**: 完成状态与完成时间的修改 MUST 经由任务实体既有操作（BT-8）发生，存取器负责其持久化。
- **FR-005**: 存取器 MUST 提供显式保存操作；变更保存后经重建可完整读回。
- **FR-006**: 存取器初始化时 MUST 自动加载既有数据（无需显式加载调用）。
- **FR-007**: 存取器 MUST 支持两种构造：内存模式（不触碰磁盘）与指定存储位置模式。
- **FR-008**: 存取器 MUST 定义于共享核心包。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: CRUD 单元测试全部通过（US1 三场景）。
- **SC-002**: 持久化重建测试通过：写入→重建→数据一致，删除→重建→已删（US2 两场景）。
- **SC-003**: 自动加载与内存模式测试通过（US3 两场景）。
- **SC-004**: 应用外壳边界检查仍为 CLEAN，应用构建零回归。

## Assumptions

- 更新操作复用任务实体的属性与方法（BT-8），存取器不重复提供逐字段 set 接口。
- "自动保存"在应用运行时由持久化机制的自动保存能力承担；显式保存用于关键节点与
  测试确定性。
- 存取器的界面绑定（驱动 UI 刷新）属于消费方特性（BT-10+），本特性只保证数据正确。
